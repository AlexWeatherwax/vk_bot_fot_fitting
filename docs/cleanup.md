Изменения подготовлены 28 октября 2026 года относительно коммита
`681ece19d9460a69c5d1773145138f1ce092e1d0`.

## Что изменилось в структуре

| Раньше | Теперь | Причина |
|---|---|---|
| `Украшения /` | `assets/source_photos/` | Явный путь к исходным фотографиям без пробела в конце имени |
| `vk_jewelry_bot/фото для калибровки/` | `assets/calibration_photos/` | Калибровочные фотографии отделены от запускаемого приложения |

| `scripts/catalog_import/work/superseded_kaffy_flat_photos/` внутри бота | `assets/source_archive/kaffy/` | Сохранены 9 уникальных старых исходников каффов |

Внутренняя структура `vk_jewelry_bot/bot/` сохранена: обработчики VK,
каталог и алгоритм примерки уже находятся в отдельных модулях.
Редактор остаётся рядом с ботом и использует общую галерею.

Перемещено 476 файлов. Для фотографий использованы прежние Git blob SHA:
изображения не перекодированы и не сжаты заново. Внутренние имена папок
исходного архива сохранены, поскольку импортёр восстанавливает их кодировку
и использует ручные соответствия товаров.

## Что сохранено

- Все **82 товара в 9 категориях**, их записи и калибровка в `manifest.json`.
- Все 82 используемых PNG и ещё 6 подготовленных PNG наборов без категории примерки.
- Три модели MediaPipe, обе цепочки, исходный алгоритм размещения украшений.
- Исходные фотографии, 8 калибровочных фото и примеры редактора.
- Ручные `options.json`, `overrides.json`, `mapping.py`, `make_overrides.py`
  и логика `4b_upright.py` — без изменений.
- Редактор, локальный импорт, дополнительный прежний импорт из VK и «Ларец».

Галерея не пересобиралась. Она содержит результаты ручной работы, которые
нельзя считать обычным воспроизводимым кэшем. Сборка шага 5 может сбросить
параметры заменяемых товаров — см. [инструкцию импорта](../vk_jewelry_bot/scripts/catalog_import/README.md).

## Исправления согласованности

- Каталог читает `brooch_side` и строит путь изображения относительно своего manifest.
- Бот перечитывает каталог после сохранения редактора: при поиске, показе списка
  и получении фотографии. Учитывается атомарная замена файла редактором.
- В JavaScript редактора исправлена незакрытая скобка в обработчике перетаскивания.
- Удалена неиспользуемая настройка `TMP_DIR` и её Docker-том; фото обрабатываются в памяти.
- `.env` читается из папки приложения, а путь `.venv` согласован с systemd.
- Вместо двух поставщиков `cv2` используется один `opencv-contrib-python`,
  необходимый также установленной версии MediaPipe.
- Добавлены отдельные тестовые зависимости. Docker копирует только код бота,
  галерею и модели; `.dockerignore` ограничивает контекст сборки.
- В Dockerfile добавлен `libgles2`: без `libGLESv2.so.2` библиотека MediaPipe
  не загружалась в проверочном Linux-окружении.

## Выполненные проверки

Проверочная среда: Linux x86_64, Python 3.12.14, vkbottle 4.11.0,
MediaPipe 0.10.35, OpenCV 4.11.0, NumPy 1.26.4 и Pillow 13.0.0.
Зависимости установлены в отдельное чистое окружение.

- `python -m pytest tests -q`: **29 пройденных тестов**, без пропусков.
  Использованы реальные модели MediaPipe, включая категорию каффов.
- Инициализация `bot.app` и вызов `app.run()` с подменённым `Bot.run`:
  экземпляр бота и обработчики создаются; сетевые подключения блокировались.
- Все активные пути галереи существуют; PNG читаются; ID товаров уникальны.
- Сверка SHA сохранённых изображений, моделей и ручных настроек.
- Синтаксическая проверка Python и JavaScript редактора/«Ларца».
- Проверки новых путей импортёра: импорт без фотоархива, понятная ошибка при
  его отсутствии и сканирование временного архива через `JEWELRY_SOURCE_DIR`.

Полный диалог с VK и визуальная оценка примерки на реальных пользователях
в эти проверки не входили. Docker-образ и systemd-служба не запускались.
Для фактического запуска используйте [инструкцию бота](../vk_jewelry_bot/README.md).
