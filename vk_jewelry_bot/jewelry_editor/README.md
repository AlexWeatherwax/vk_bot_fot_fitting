# Редактор украшений для ВК-бота

## Статус
Подготовлены исходники под ваш pipeline.py. Проверены синтаксис Python и реальные функции
сохранения (TEST_REPORT.txt). Полный запуск с ботом, MediaPipe и браузером НЕ выполнялся:
проекта бота и моделей .task здесь нет. Проверить на сервере на копии gallery до публикации.
Приложение не установлено автоматически.

## Установка
Linux (fcntl), Python 3.10–3.12, рекомендуем 3.11. Распакуйте в корень vk_jewelry_bot:
папка jewelry_editor рядом с bot. Нужен файл bot/tryon/pipeline.py (не pypline.py).
Должны быть установлены зависимости бота, присутствовать landmarks_*.py, compose.py,
jewelry/models.py, catalog.py, manifest, картинки и три bot/tryon/models/*.task.
Цепочки при необходимости: bot/tryon/assets/chain_silver.png / chain_gold.png.

```bash
cd /путь/к/vk_jewelry_bot
source .venv/bin/activate
python -m pip install -r jewelry_editor/requirements.txt
export EDITOR_USER=author
# Случайный пароль: python -c 'import secrets; print(secrets.token_urlsafe(32))'
read -s -p 'Пароль редактора: ' EDITOR_PASSWORD; echo
export EDITOR_PASSWORD
python -m uvicorn jewelry_editor.app:app --host 127.0.0.1 --port 8765 --workers 1
```

Пароль минимум 16 символов. Вход через стандартное окно браузера Basic Auth.
Тест с другого компьютера: ssh -L 8765:127.0.0.1:8765 пользователь@сервер,
затем http://127.0.0.1:8765/. Для интернета — только HTTPS; порт напрямую не публиковать.
Редактор запускается ОТДЕЛЬНЫМ процессом от бота, строго один worker, без --reload.
Он временно перехватывает overlay_image и детекторы под блокировкой, получая метки
без дублирования формул. Несколько экземпляров редактора не поддерживаются.

## Изменения catalog.py
В конструктор JewelryItem добавьте:

```python
                brooch_side=entry.get("brooch_side", "left"),
```

Для первого теста после сохранения можно перезапустить бота. Для автообновления:
перед raw = json.loads(...) внутри reload() добавьте:

```python
        stat = self.manifest_path.stat()
        stamp = (stat.st_mtime_ns, stat.st_size, stat.st_ino)
```

После построения self.items, после закрывающей ] comprehension:

```python
        self._manifest_stamp = stamp
```

В класс Catalog добавьте:

```python
    def reload_if_changed(self) -> None:
        stat = self.manifest_path.stat()
        stamp = (stat.st_mtime_ns, stat.st_size, stat.st_ino)
        if stamp != getattr(self, "_manifest_stamp", None):
            self.reload()
```

Первой исполняемой строкой find() после docstring добавьте self.reload_if_changed().
Один раз перезапустите бота после изменения кода. При прямом чтении catalog.items
вызывайте reload_if_changed() там тоже. Перед примеркой заново получайте item по id
из актуального catalog.items: старый объект в состоянии диалога сам не обновится.
Без обработчиков невозможно проверить все места доступа к каталогу.

## Сетевой запуск
В существующий HTTPS server {} Nginx добавьте deploy/nginx.conf. Домен и сертификат
настраиваются отдельно. Ссылка: https://ваш-домен/editor/ (со слешем).
Для автозапуска адаптируйте deploy/jewelry-editor.service — пользователь и пути примеры.
В /etc/jewelry-editor.env: EDITOR_USER и EDITOR_PASSWORD по одному на строку, без export.
Ограничьте доступ к файлу пароля; не храните его в Git и не передавайте в URL.
Редактор должен писать в gallery, бот читать созданные PNG/JSON. Проще запускать оба
от одного системного пользователя. Не публикуйте gallery как статическую папку:
там копии и черновики. На reverse proxy добавьте rate limit или доступ через VPN/IP.
Авторизация общая: все с паролем могут менять все украшения. Личных аккаунтов и
разделения по владельцу нет. Отзыв доступа — сменить пароль и перезапустить сервис.

## Работа
Загрузите PNG/WebP с прозрачным фоном, название, категорию. Перетаскивайте синюю метку,
масштаб/угол меняйте полями. При движении двигается метка; после отпускания сервер
перерисовывает украшение вашим pipeline. Это не непрерывный видеорендер.
По умолчанию — синтетическая модель в три четверти с открытым ухом. Пробный PNG — examples/jewelry.png, выбирается вручную.
Для рук/плеч/макушки нужны соответствующие фото. Если профиль не обнаружен, попробуйте
три четверти. Категория автоматически не определяется. Сторону left/right выбирайте
по превью: комментарии бота не везде согласованы по анатомии и стороне кадра.

Обрезка прозрачных полей включена для новой загрузки ДО калибровки; при открытии записи
поля не меняются. До 12 МБ / 12 Мп, сторона PNG до 4096. Фото модели нормализуются по EXIF
и уменьшаются до 1800 px. Картинки сохраняются PNG. Порог alpha=160 из pipeline сохранён.

Совпадение имени глобальное точное после NFKC, casefold и нормализации пробелов.
Нечёткий Catalog.find для перезаписи НЕ используется. Предупреждение при вводе;
для сохранения нужна галочка. Сам ввод JSON не меняет. Обновление сохраняет id и
неизвестные поля. Новая картинка получает уникальное custom/<uuid>.png — без старого кэша
split_pair. Старые PNG сохраняются. Переименовать открытую запись можно, но не в имя
другой записи. Несколько старых одинаковых имён требуют ручного исправления.
У пары серёг общие настройки; независимо двигать обе текущий формат не позволяет.
options.json / overrides.json не меняются: используются готовые прозрачные картинки.

JSON записывается атомарно, Linux-блокировка .editor.lock, проверка версии всего manifest.
При конфликте обновите список и проверьте данные; редактируемую запись безопаснее открыть
заново. Остальные программы записи должны брать ту же блокировку либо работать при
остановленном редакторе. Перед заменой создаётся .editor-backups/<hash>.json.
Резервируйте gallery целиком. Старые PNG и копии автоматически не чистятся.
Черновики живут час с последнего использования, максимум 80 на процесс; чистятся
при загрузках и перезапуске. Следите за свободным местом.

## Проверка на копии gallery
Новое имя: +1 запись; то же с регистром/пробелами: предупреждение; без галочки обновление
запрещено; с галочкой id и количество записей прежние, параметры новые.
Две вкладки: устаревшее сохранение получает конфликт версии. Проверить все категории
на подходящих фото, итог через ВК и прямое чтение catalog.items отдельно.

## Примечания
mediapipe>=0.10.30 в присланном requirements исключает указанную в комментарии проверенную
0.10.21. Не обновляйте рабочую MediaPipe вслепую: используйте проверенную версию сервера.
compose.py использует alpha и как маску paste, и в alpha_composite — края могут ослабляться.
Редактор это не меняет ради совпадения с ботом; исправлять отдельно с визуальными тестами.
Ориентиры уха — приближение Face Mesh, не точный детектор уха.
