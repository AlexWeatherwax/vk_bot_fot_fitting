# Передача админки владельцу Windows без домена

Постоянная схема: Windows владельца → SSH-туннель → редактор на VPS.
Каталог, обработка фотографий и бот находятся на VPS. Компьютер разработчика
после передачи не используется. Редактор слушает только `127.0.0.1:8765`,
бот работает независимо от открытого туннеля. Публичный порт редактора не нужен.

Этот документ предназначен для специалиста, который разворачивает сервис.
Владелец получает установленный ярлык и короткую инструкцию из `../windows/README.md`.
Файлы клиента подготовлены к настройке; передачу нельзя считать завершённой
до проверки на настоящем Windows-компьютере владельца и рабочем VPS.

## 1. Подготовить компьютер владельца

Поддерживаются Windows 10 (1809 и новее) и Windows 11 с Windows PowerShell 5.1
и компонентом **OpenSSH Client**. Нужен именно клиент, сервер OpenSSH на Windows
устанавливать не требуется. При отсутствии компонента включите его через
«Дополнительные компоненты» Windows при первоначальной настройке.

Запустите `../windows/Install.cmd` на компьютере владельца. Установка хранится
в `%LOCALAPPDATA%\Imladris`. Первый запуск создаёт собственную пару ключей
`owner_ed25519` / `owner_ed25519.pub`. При повторной установке ключ сохраняется.
Передайте на VPS только содержимое `.pub`. Приватный ключ остаётся у владельца;
он не должен попадать в Git, передаваемый ZIP или компьютер разработчика.

Ключ без отдельной парольной фразы нужен для запуска без терминала. Он разрешает
только соединение с редактором благодаря отдельной серверной учётной записи,
описанной ниже. Файлы ключа и настройки на Windows доступны только владельцу.
Пароль HTTP-входа в редактор хранится отдельно и не записывается в настройки клиента.

## 2. Ограничить серверную учётную запись

Пример для Debian 12 после установки и проверки самого редактора. Следующие
команды выполняет администратор VPS под root, а не владелец магазина.
Если пользователь уже существует, сначала проверьте его назначение и домашний каталог.

```sh
useradd --system --user-group --create-home --home-dir /var/lib/imladris-editor --shell /usr/sbin/nologin imladris-editor
usermod --password '*' imladris-editor
install -d -m 0700 -o imladris-editor -g imladris-editor /var/lib/imladris-editor/.ssh
install -m 0600 -o imladris-editor -g imladris-editor /root/owner_ed25519.pub /var/lib/imladris-editor/.ssh/authorized_keys
```

`*` — непригодный для входа маркер пароля, не пустой пароль. Вход по паролю
для этой учётной записи дополнительно запрещается в настройках SSH.
Пользователь не входит в sudo и не имеет прав на файлы каталога.

Добавьте следующий блок **в самый конец** `/etc/ssh/sshd_config`, предварительно
сохранив копию файла. Не помещайте `Match` в автоматически подключаемый в начале
файл `sshd_config.d`: последующие глобальные директивы могут оказаться внутри блока.

```text
Match User imladris-editor
    AuthenticationMethods publickey
    PubkeyAuthentication yes
    PasswordAuthentication no
    KbdInteractiveAuthentication no
    AllowTcpForwarding local
    AllowStreamLocalForwarding no
    PermitOpen 127.0.0.1:8765
    PermitListen none
    AllowAgentForwarding no
    X11Forwarding no
    PermitTTY no
    PermitTunnel no
    PermitUserRC no
    MaxSessions 0
```

Проверьте синтаксис и применившиеся ограничения до перезагрузки конфигурации:

```sh
/usr/sbin/sshd -t
/usr/sbin/sshd -T -C user=imladris-editor,host=localhost,addr=127.0.0.1
systemctl reload ssh
```

Оставьте текущую административную сессию открытой до проверки нового подключения.
Если глобальные `AllowUsers`/`AllowGroups` или настройки хостера ограничивают
доступ, добавьте эту учётную запись в соответствующий разрешённый список.
`MaxSessions 0` запрещает shell, команды и SFTP, сохраняя туннель `ssh -N`.

## 3. Подготовить доверенные настройки подключения

Скопируйте `../windows/config.example.json` в `../windows/config.json` в отдельной
папке передачи, а не в публичном репозитории. Укажите публичный IP VPS, порт SSH,
`SshUser=imladris-editor`, `LocalPort=8765`, `RemotePort=8765`.

На VPS прочитайте `/etc/ssh/ssh_host_ed25519_key.pub` через уже проверенную
административную сессию либо VNC-консоль Spaceweb. Создайте `windows/known_hosts`
с одной строкой:

```text
IP_СЕРВЕРА ssh-ed25519 ПУБЛИЧНЫЙ_КЛЮЧ_СЕРВЕРА
```

Для SSH на нестандартном порте первая часть — `[IP_СЕРВЕРА]:ПОРТ`.
Это ключ **сервера**, а не `owner_ed25519.pub`. Адрес должен совпадать с `ServerHost`.
Не принимайте результат непроверенного `ssh-keyscan` за подтверждение сервера
и не отключайте проверку ключа. После переустановки VPS новый ключ сверяется
через кабинет хостинга и обновляется в установленном `known_hosts`.

Повторно запустите `Install.cmd` из папки с подготовленными `config.json`
и `known_hosts` на Windows владельца. Приватный ключ, созданный первым запуском,
должен сохраниться. Проверьте ярлык на рабочем столе.

## 4. Проверка перед передачей

До подключения выполните в Windows PowerShell проверку настроек и экранирования
аргументов (не требует сервера и не изменяет установленный ключ):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Test-Client.ps1
```

Ожидается `PASS: 22 client checks`. Затем проверьте сам интерфейс и соединение:

- Ярлык запускает подключение и открывает именно админку. Браузер просит её логин
  и пароль; эти данные передаются владельцу отдельно.
- Второй щелчок по ярлыку не создаёт ещё один туннель. Занятый чужим процессом
  локальный порт не открывается как админка.
- После обрыва интернета и его восстановления соединение восстанавливается;
  при недоступности VPS показывается понятный статус, интерфейс не выдаёт успех.
- Под ограниченной учётной записью запрещены shell, SFTP, обратный туннель
  и перенаправление к другим портам сервера.
- Добавление украшения, сохранение подгонки и удаление проверены на рабочем
  каталоге владельцем; изменение видно в боте.
- После перезагрузки VPS бот и редактор запускаются автоматически. После
  перезагрузки Windows работает тот же ярлык. Проверка проходит при выключенном
  компьютере разработчика.
- У владельца есть кабинет Spaceweb, собственный ключ, пароль редактора,
  исходники, резервная копия галереи и инструкция восстановления. Настроены
  серверные бэкапы и проверено восстановление в отдельную папку. Ключ на Windows
  хранится в резервной копии владельца; при его потере новый публичный ключ
  устанавливается через административный доступ/VNC хостинга.
