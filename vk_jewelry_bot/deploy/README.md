# Имладрис: первое развёртывание на Saturn

Целевая ОС — Debian 12, Python 3.11. Бот и редактор работают на одном VPS,
пользователем `jewelry`, с общей галереей. Редактор слушает только
`127.0.0.1:8765`; владелец открывает его через Windows-ярлык и SSH-туннель.
Домен и компьютер разработчика для повседневной работы не используются.

Эта инструкция предназначена для специалиста, который устанавливает или передаёт
сервис. Текущая установка прошла проверку сервера, Windows-клиента и автозапуска;
при новом развёртывании эти проверки необходимо повторить для нового окружения.

## Данные для подключения

- Публичный IP VPS, ОС, SSH-пользователь с административными правами и порт.
- Доверенный ключ/отпечаток сервера, сверенный через кабинет или VNC хостинга.
- Административный приватный SSH-ключ как локальный файл. В переписке достаточно
  указать путь к файлу; текст приватного ключа не публикуется. Публичная часть
  `.pub` устанавливается на сервер и сама по себе не позволяет подключиться.
- Токен и ID сообщества ВК, выбранного для запуска, и отдельные логин/пароль
  редактора. Секреты настраиваются отдельно от архива приложения.

Ключ Windows-владельца с разрешённым только туннелем отличается от
административного ключа развёртывания: он не позволяет устанавливать пакеты.
Основной доступ к хостингу и восстановлению сервера остаётся у владельца.

## 1. Подготовить архив

На компьютере с исходным проектом:

```sh
python3 scripts/build_deploy_bundle.py --output /tmp/imladris-runtime.tar.gz
```

Архив содержит код, активную галерею, локальные модели, интерфейс, установщик
и семь необходимых референсов. Ключи SSH, `.env`, локальные окружения,
фотографии временных примерок и локальные архивы в него не входят.
Проверка на сервере использует настоящие модели, не подключается к ВК
и не изменяет подгонку украшений.

## 2. Первичная установка

Передайте архив на новый VPS через SCP/SFTP по административному SSH-доступу.
Проверьте ключ сервера до первой передачи секретов. На VPS под root:

```sh
test ! -e /opt/vk_jewelry_bot
tar -xzf /root/imladris-runtime.tar.gz -C /opt
bash /opt/vk_jewelry_bot/deploy/install.sh
```

Распаковка предназначена только для первой установки на пустой путь.
При обновлении работающего сервиса исходная галерея не должна заменять
галерею, изменённую владельцем. Сначала сделайте согласованную резервную копию.
Каталоги `data/consent/` и `data/sessions/` содержат рабочие согласия, отзывы
и открытые сеансы. Их нельзя заменять локальными файлами или включать
в распространяемый архив.
Используйте SQLite backup API или остановку бота для согласованной копии БД.

Установщик создаёт Python-окружение, ставит обе группы зависимостей, создаёт
пользователя `jewelry` и устанавливает две службы. Код доступен службе на чтение,
каталог и `data/` — на запись. Существующие секреты сохраняются.
Автоматический запуск до настройки доступа к ВК не выполняется.

Создайте `/etc/imladris/bot.env` по `bot.env.example` и
`/etc/imladris/editor.env` по `editor.env.example` через защищённое подключение.
Владелец обоих файлов — `root:root`, права — `0600`.
Нужен новый пароль редактора длиной не менее 16 символов; пароль локальной QA
не используется. `EDITOR_GALLERY` не задавайте: редактор должен менять тот же
каталог, который читает бот. Корневой `.env` на сервер не копируется.
Формат конфигурации — UTF-8 без BOM, `KEY=VALUE` без кавычек, пробелов и
обратных слешей. Комментарии начинаются с `#` на отдельной строке. Для пароля
подходит результат `secrets.token_urlsafe(32)`; его записывают непосредственно
в закрытый env-файл, не в переписку и не в архив приложения.

Проверьте весь каталог на Linux, ещё не запуская бота:

```sh
cd /opt/vk_jewelry_bot
runuser -u jewelry -- .venv/bin/python scripts/server_smoke.py --output data/audit/saturn-smoke
```

Отчёт и результаты появятся в `data/audit/saturn-smoke`. Требуются ноль ошибок,
работа seccomp и успешная обработка всех частей наборов. Проверка на прежнем
Linux ARM не заменяет этот прогон на фактическом VPS.

## 3. Включить постоянную работу и автозапуск

Перед запуском остановите другие копии бота с тем же VK-токеном, в том числе
локальный тестовый Long Poll. Две копии не должны забирать одни сообщения.
После заполнения конфигурации и успешной проверки выполните:

```sh
bash /opt/vk_jewelry_bot/deploy/activate.sh
```

Скрипт проверяет заполнение и права конфигурации без вывода секретов,
отсутствие старых включённых служб, затем выполняет `systemctl enable --now`
для `imladris-bot.service` и `imladris-editor.service`.

Обе службы привязаны к `multi-user.target`: запускаются после каждой загрузки
VPS без входа пользователя в SSH. `Restart=always` перезапускает завершившийся
процесс через пять секунд; явная команда `systemctl stop` останавливает его.
Редактор работает строго с одним worker. Компьютер Windows нужен только для
открытия интерфейса; запуск бота от него не зависит.

## 4. Проверить настоящий перезапуск

До перезагрузки и после восстановления SSH должны выполняться обе проверки:

```sh
systemctl is-enabled imladris-bot.service imladris-editor.service
systemctl is-active imladris-bot.service imladris-editor.service
```

Ожидаются две строки `enabled` и две строки `active`. Затем убедитесь, что
редактор отвечает локально с HTTP 401 и заголовком `X-Imladris-Editor: 1`,
а ВК-бот отвечает на сообщение владельца и обрабатывает фото.
Один только статус `active` не подтверждает правильность VK-токена или моделей.

После согласования краткого перерыва выполните `systemctl reboot`.
Подключитесь заново, повторите проверки и откройте админку на Windows владельца.
Подтвердите сохранение украшения и его видимость в боте. Проверьте также
одновременную примерку в ВК и предпросмотр в редакторе, включая потребление RAM.

Для диагностики используются `journalctl -u imladris-bot.service -b` и
`journalctl -u imladris-editor.service -b`. Журналы проверяются на сервере;
не публикуйте сообщения с пользовательскими фото или секретами.

## 5. Передача владельцу

Настройте отдельного пользователя только для SSH-туннеля и Windows-клиент
по `jewelry_editor/deploy/windows-owner.md` в исходном проекте. Публичный ключ
владельца создаётся на его Windows-компьютере; приватная часть остаётся у него.

Настройте автоматические резервные копии всей рабочей галереи, включая
`manifest.json`, `custom/` и `.editor-backups/`, исключив `.editor-staging/`.
На время формирования согласованной копии удерживайте shared-lock
`.editor.lock`, который использует редактор. Отдельно сохраняются исходный
пакет приложения, конфигурации служб и защищённые копии env-файлов.
Нужно проверить восстановление в отдельную папку и передать владельцу инструкцию.

Передача завершена после реальной проверки VPS и Windows, работы с ВК,
перезагрузки, резервного копирования и восстановления. Все основные учётные
записи, платежи и способы восстановления принадлежат владельцу магазина.


## 6. Сменить сообщество ВК

Рабочее сообщество — [studio_imladris](https://vk.ru/studio_imladris),
ID `23036479`. Для подключения другого сообщества:

1. Включите сообщения сообщества, Long Poll API и событие входящего сообщения
   `message_new`. Для текущего runtime используется версия API `5.199`.
   Получите ключ именно целевого сообщества с правами `messages` и `photos`;
   для изменения настроек Long Poll через API нужны соответствующие права управления.
2. Проверьте принадлежность ключа через `groups.getById`, его права через
   `groups.getTokenPermissions`, настройки через `groups.getLongPollSettings`.
   Успешный `groups.getLongPollServer` с целевым ID подтверждает доступ к его
   Long Poll. Не выводите в журналы токен, ключ Long Poll и полный ответ API.
3. Сохраните защищённую копию прежнего `/etc/imladris/bot.env`. Обновите в нём
   только `VK_TOKEN` и `VK_GROUP_ID`, сохранив остальные параметры. Владелец файла
   — `root:root`, права — `0600`. Не передавайте токен в аргументах shell-команд,
   Git, URL или скриншотах. Пользуйтесь закрытым каналом настройки сервера.
4. Перезапустите только бота:

   ```sh
   systemctl restart imladris-bot.service
   systemctl is-active imladris-bot.service
   ```

5. Проверьте состояние службы и отсутствие ошибок, затем отправьте «начать»
   в сообщения новой группы, подтвердите согласие и получите готовое фото
   примерки. Статус `active` сам по себе не проверяет всю цепочку доставки.

Файл состояния Long Poll выбирается по ID новой группы; старое состояние
переносить не нужно. Согласия тоже привязаны к ID сообщества: в новой группе
потребуется подтверждение. Сеансы также привязаны к группе и открываются
командой «Начать». Каталог, рабочие SQLite-базы, админку и настройки
Windows при такой смене не заменяют. Компьютер разработчика для переключения
и последующей работы не нужен, если административный доступ уже передан владельцу.
