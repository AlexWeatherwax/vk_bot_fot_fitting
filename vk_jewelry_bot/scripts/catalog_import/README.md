# Импорт каталога из локальных фотографий

Этот набор скриптов превращает папку с «сырыми» фотографиями студии
(`assets/source_photos/` в корне репозитория) в готовый каталог:
PNG с прозрачным фоном в `bot/jewelry/gallery/` + записи в `manifest.json`.
Готовая галерея уже включена в проект; запускать импорт для запуска бота не нужно.

Отличается от соседнего `scripts/imladris_import/`, который выкачивал те же
украшения из группы ВК: там исходником были одиночные фото с сайта, здесь —
локальный архив студии, где **у каждого товара несколько ракурсов**, и
главная задача — выбрать из них лучший.

## Структура исходной папки

```
assets/source_photos/
├── Серьги/
│   ├── Прибой/            <- подпапка нижнего уровня = один товар
│   │   ├── IMG_0001.jpg   <- несколько фото одного и того же украшения
│   │   └── ...
│   └── ...
├── Кулоны 2/
└── ...
```

Как снимать новые товары, чтобы импорт проходил без ручной доводки, —
см. [СЪЁМКА.md](СЪЁМКА.md).

Имена подпапок в архиве испорчены (`Па•§†≠®•` вместо `Предание`): это байты
CP866, прочитанные как MacCyrillic — типично при распаковке архива на macOS.
`common.demojibake()` чинит их обратно, файлы при этом не переименовываются.

Путь вычисляется относительно репозитория и не зависит от текущей папки.
Для внешнего архива задайте `JEWELRY_SOURCE_DIR`; относительное значение этой
переменной отсчитывается от папки, из которой запускается команда:

```bash
JEWELRY_SOURCE_DIR="/полный/путь/к/фотографиям" ../../../.venv-import/bin/python 1_scan.py
```

Отсутствие исходного архива проверяется в шаге 1. Работа с готовой галереей
и импорт модуля `paths.py` этого архива не требуют.

## Какие данные хранить

| Путь | Назначение |
|---|---|
| `assets/source_photos/` от корня репозитория | исходные фотографии украшений |
| `assets/calibration_photos/` от корня репозитория | пробные фотографии для шагов 7 и 8 |
| `assets/source_archive/kaffy/` от корня репозитория | прежние исходные фото каффов; сохраняются для истории и сравнения |
| `examples/` | две постоянные иллюстрации ракурсов кольца для PDF-задания |
| `options.json`, `overrides.json`, `make_overrides.py`, `mapping.py`, `4b_upright.py` | ручные настройки выбора, вырезания, поворота и соответствия товаров |
| `bot/jewelry/gallery/` от папки бота | готовые изображения и актуальная калибровка в `manifest.json` |
| `work/` | временные вырезы, копии галереи, индексы, логи и отчёты; исключены из Git |

После нового клонирования для подготовки очередного импорта начните с шага 1.
Он создаст `work/items.json` с путями текущего компьютера. Старые `items.json`,
`screen.json`, `picks.json` содержали абсолютные пути другой машины и удалены
из Git вместе с производными изображениями.

Текущая галерея содержит ручную доводку. Шаг 5 заменяет картинки и сбрасывает
поля подстройки заменяемых товаров; перед его запуском сохраните изменения
галереи в отдельном коммите. Повторная сборка не гарантирует точного
восстановления ручных правок, выполненных вне конвейера.

## Окружения

Скриптам нужны библиотеки, которых у самого бота нет. Для подготовки изображений
и для проверки через MediaPipe используются отдельные окружения. Следующие
команды выполняются из корня репозитория; окружения исключены из Git:

```bash
python3.12 -m venv .venv-import
.venv-import/bin/pip install "rembg[cpu]" onnxruntime Pillow numpy scipy opencv-python-headless reportlab

python3.12 -m venv .venv-mp
.venv-mp/bin/pip install "mediapipe>=0.10.30,<1.0" "numpy<2" opencv-contrib-python Pillow
```

**Осторожно с версией mediapipe.** На macOS `mediapipe` 1.0.x падает при
создании HandLandmarker/FaceLandmarker с `Check failed: service_ Service is
unavailable` — даже с `delegate=BaseOptions.Delegate.CPU`. Проверены и
работают 0.10.21 и 0.10.35, поэтому в `requirements.txt` бота стоит верхняя
граница `<1.0`.

## Как выбирается кадр (шаг 3)

**Главный критерий — ракурс, а не чистота фона.** Кадр должен показывать
украшение в том виде, в каком его носят:

| Категория | Нужный кадр |
|---|---|
| серьги | висят (на подставке, на ветке, на стекле) — не лежат плашмя на столе |
| кулон, колье | висят вертикально на цепочке/шнуре, подвесом вверх |
| кольцо | надето на палец: на кадре дужка обрывается ровно там, где уходит за палец, — это и делает примерку правдоподобной |
| браслет | надет на запястье или обёрнут вокруг кружки — то есть дугой, а не прямым отрезком |
| диадема, венец | анфас |
| брошь | анфас, а не ребром |
| заколка, шпилька | сбоку — так её и видно в волосах |
| кафф | надет на ухо (или на макет уха), вид сбоку — анфас раковину не видно |

Реквизит (кружка, подставка, блюдце, манекен, рука) — вторичен: он убирается
приёмами из `options.json`. **Неверный ракурс не чинится ничем**: из
фотографии, снятой сверху, нельзя получить вид спереди — для этого нужна
модель генерации изображений, которой в конвейере нет.

`3_pick.py` считает для каждого кадра штрафы: кожа в кадре, «монолитность»
силуэта (вырезалось блюдце/кружка/манекен, а не украшение), касание края
кадра, слишком мелкий объект, — и премию за резкость. **Автоматика тут только
подсказка:** ракурс она не оценивает вовсе. Итоговый выбор задан вручную в
`make_overrides.py` (просмотрено глазами по контактным листам). Чтобы
поменять кадр у товара, правьте `make_overrides.py`, затем:

```bash
../../../.venv-import/bin/python make_overrides.py && ../../../.venv-import/bin/python 3_pick.py
```

## Как чинятся сложные кадры (шаг 4)

Настройки — в `options.json`, по ключу товара:

- `crop` — предварительно обрезать кадр. Единственный способ убрать реквизит,
  стоящий вплотную (кружка за серьгами, книга под подставкой): модель считает
  его частью того же объекта, и после вырезания сделать уже ничего нельзя.
- `luma_min` — выбросить из маски всё темнее порога. Спасает съёмку на
  чёрном манекене (диадемы) и на тёмном камне: украшение — светлый металл,
  подложка почти чёрная, по яркости они делятся начисто.
- `remove_skin` — вычесть кожу. Кадр «кольцо на пальце»: фон модель уже
  убрала, внутри маски осталась рука и кольцо, кожу вычитаем — остаётся кольцо.
- `keep_polys` / `erase_polys` — оставить/стереть внутри многоугольников
  (координаты в долях кадра). Ручной «ластик» для случаев, где ничего
  автоматического не сработало.
- `trim_chain` — радиус эрозии, чтобы отрезать длинную цепочку у кулона:
  бот рисует свою цепочку сам (поле `chain_color`), чужая на картинке мешает.
- `reflection_split` — отрезать отражение предмета в глянцевом столе.
- `min_component` — какую долю от крупнейшей детали считать мусором.
  У пары серёг деталей две, поэтому по умолчанию 0.12, а не «только крупнейшая».

## Разворот к вертикали (шаг 4b)

Даже на удачном кадре украшение может лежать под углом. `4b_upright.py`
считает главную ось каждой детали (PCA по маске) и доворачивает картинку до
вертикали — минимальным углом. Это поворот в плоскости кадра: ракурс он не
меняет и новых данных не выдумывает.

**Сторона «где верх» задаётся вручную**, в `UPRIGHT_OVERRIDES`. Автоматику
пробовали — «тяжёлый конец вниз» (у серьги внизу бусины, вверху тонкий
крючок) — и она переворачивала вверх ногами кулон «Золотое сердце»,
«Шёлковые травы» и серьги «Лесное лето», у которых верх как раз массивнее
низа. Надёжного признака нет, поэтому 180° ставится руками по контактному
листу.

Повторный запуск безопасен: что уже развёрнуто, записано в
`work/upright.json` вместе со временем правки файла. Пересчитали вырез
шагом 4 — запись устаревает, и картинка обрабатывается заново с чистого
неповёрнутого файла.

## Что не попадает в каталог

Наборы обрабатываются, но записей в `manifest.json` не получают: набор — это
несколько разных изделий сразу, единой точки крепления для него нет. Готовые
PNG складываются в `bot/jewelry/gallery/imladris/_ready_no_category/`.

Каффы (категория `kaffy`) до пересъёмки 6.09.2026 были в том же положении —
точки крепления не было вовсе. Заказчик переснял все 9 каффов надетыми на
ухо, вид сбоку (см. `9_reshoot_brief.py`, группа `CUFF`), и теперь у
категории есть точка крепления — та же мочка, что и у серьги
(`bot/tryon/pipeline.py`, `_apply_kaffy`): самая украшенная часть каффа
(гроздь бусин) садится на мочку, а дужка сама уходит вверх на раковину.
Записи в `manifest.json` есть, как у любой другой категории.

## Кольца: почему вырез делается из кадра «на руке»

Кольцо, снятое на блюдце сверху, при наложении читается как наклейка поверх
руки: видно всю окружность дужки, включая ту часть, которая должна прятаться
за пальцем. На кадре «надето на палец» этой проблемы нет — палец уже закрыл
собой заднюю часть дужки, и вырез обрывается ровно по краям пальца.

Дальше остаётся совместить обрывы с краями пальца клиента: в боте ширина
картинки кольца приравнивается к ширине пальца (`RING_WIDTH_FRACTION = 1.0`
в `bot/tryon/pipeline.py`), а точка посадки сдвинута с середины фаланги ближе
к первому суставу (`RING_ALONG_PHALANX` в `bot/tryon/landmarks_hand.py`) —
иначе кольцо садится на костяшку. Оба числа подобраны по калибровочным фото.

Тот же приём работает для браслета, снятого на запястье.

## Как проверять калибровку (шаги 7-8)

Шаг 8 примеряет весь каталог на пробные фото и раскладывает результат по
категориям: одна миниатюра на товар, кадр автоматически приближен к нужной
части тела (лицо / шея и плечи / кисть) по тем же landmark-ам, которыми бот
ищет точку крепления. Под каждой миниатюрой подписаны текущие поля
подстройки из `manifest.json` — `scale`, `dx`, `dy`, `rot`. Править их нужно
там же, в `manifest.json`; категорийные коэффициенты (какую долю от ширины
лица занимает серьга и т.п.) — в `bot/tryon/pipeline.py`.

На таком листе сразу видно то, что по одному товару не заметно: например,
что три пары серёг ложились поперёк лица, потому что на картинке они слиплись
в одну область и не разбирались на две детали.

Для проверки каффов (категория `kaffy`, добавлена после пересъёмки 6.09.2026)
на профильном фото из `assets/calibration_photos/` выполните:

```bash
../../../.venv-mp/bin/python 7_calibrate_preview.py kaffy
```

и подстройте `anchor_scale`/`offset_x`/`offset_y`/`rotation_offset` в
`manifest.json` по результату — так же, как для любой другой категории.

## Известные ограничения

- **Новый ракурс сгенерировать нечем.** Если ни на одном кадре товара нет
  нужного вида (например, кольцо снято только сверху на блюдце), конвейер
  этого не исправит: он умеет выбирать, вырезать, поворачивать в плоскости
  и подрезать, но не дорисовывать. Такие товары перечислены в
  `bot/jewelry/gallery/imladris/NEEDS_REVIEW.md` — им нужна пересъёмка.
- Модель удаления фона универсальная, а не «для украшений». Там, где реквизит
  фактурой и яркостью совпадает с украшением (серебро кольца ≈ серебро
  блюдца), автоматика не помогает — нужен `crop`/`keep_polys` или ручная
  кисть в Photopea/GIMP.
- После замены картинки у существующей записи поля подстройки
  (`anchor_scale`, `offset_*`, `rotation_offset`) сбрасываются к значениям по
  умолчанию для категории: старые подбирались под старый вырез. После импорта
  каталог стоит один раз прогнать по калибровочным фото и подстроить заново.
- **Точка крепления каффа.** Перебрала три варианта: первая прикидка без
  калибровочного фото (mediapipe не запускался в среде, где писался код, см.
  предупреждение про `Check failed: service_ Service is unavailable` выше);
  затем отдельная точка «раковина», пересчитанная по образцу заказчика —
  3D-модели уха с готовой маской посадки каффа «Зимний лес» — но на живом
  фото она сажала кафф то на щёку, то выше уха, чем нужно. В итоге (по
  заказчику: самая украшенная часть каффа — гроздь бусин — должна сесть
  примерно на мочку) кафф просто садится на ту же точку мочки, что и
  серьга (`_LOBE_DOWN`/`_LOBE_OUT` в `bot/tryon/landmarks_face.py`) — дужка
  сама уходит вверх на раковину. Проверено на живом фото в три четверти
  (`7_calibrate_preview.py kaffy`), село правдоподобно на всех 9. Если для
  конкретного каффа посадка всё равно не та (у 9 моделей разное соотношение
  длины проволоки и размера грозди) — подстройте
  `offset_x`/`offset_y`/`anchor_scale` в `manifest.json` для этой записи.
