# Имладрис: мастерская эльфийских украшений

ВК-бот для виртуальной примерки и интерфейс автора для управления украшениями.
Рабочее сообщество: [studio_imladris](https://vk.ru/studio_imladris), ID `23036479`.
Токен сообщества и данные входа задаются отдельно и не входят в репозиторий.

## Как пользоваться ботом

1. В сообщениях сообщества напишите **«начать»**, в том числе в прежнем диалоге.
2. Прочитайте согласие на обработку персональных данных и нажмите кнопку
   **«Начать» под текстом**. Напечатанная команда сама по себе не даёт согласие.
3. Напишите **«каталог»** или название категории: «серьги», «кулоны», «наборы».
4. Отправьте название украшения или готового набора, затем фото по подсказке.
   Бот вернёт результат в тот же диалог.

**«Завершить примерку»** закрывает сеанс: бот перестаёт отвечать на обычные
сообщения, и можно общаться с владельцем мастерской. Для возвращения
напишите **«Начать»**. Пока сеанс не открыт, обычная переписка не запускает бота.

**«Отмена»** сбрасывает выбранное украшение внутри сеанса. **«Согласие»**
показывает условия повторно.
**«Отозвать согласие»** останавливает текущую примерку и блокирует обработку
новых фото до повторного нажатия кнопки согласия. Подтверждение сохраняется
после перезапуска; изменение текста согласия требует нового подтверждения.

**«Позови мастера»** выделяет обращение в сообщениях сообщества. При ручной
проверке владелец увидел его в «Непрочитанных». Мастер отвечает в том же диалоге;
команда доступна внутри открытого сеанса и до согласия на примерку.

Совместная примерка доступна **только для готовых наборов**. Комплект выбирается
по одному названию. Совместимые части примеряются на одном фото в фас;
«Ледяное озеро» последовательно запрашивает лицо и запястье. Остальные украшения
примеряются по одному. Для каффов нужно открыть правое ухо, для шпилек —
показать боковой пучок. Следуйте подсказке выбранной позиции.

## Админка автора

Админка позволяет загружать украшения на прозрачном фоне, задавать название
и тип, двигать, масштабировать и поворачивать их прямо на референсе.
После нажатия **«Добавить в каталог»** или **«Сохранить изменения»** параметры
посадки записываются в общий каталог. Можно редактировать и удалять позиции;
изменения подхватываются ботом без перезапуска.

В существующих наборах можно менять название и настраивать отдельные части.
Создание новых наборов через интерфейс пока не предусмотрено. Удаление набора
удаляет всю карточку комплекта. Локальные копии manifest создаются перед
изменениями; внешнее резервное копирование настраивается отдельно.

Для владельца с Windows предусмотрен ярлык, открывающий браузер через
SSH-туннель. Админка и обработка работают на сервере; домен и компьютер
разработчика для ежедневной работы не нужны. Окно подключения оставляют
открытым во время редактирования. Бот продолжает работать при выключенном ПК.

## Развёртывание и обновление

Поддерживаемая среда обработки — **Linux, Python 3.11**, для текущей установки
используется Debian 12. Бот и редактор — две отдельные службы:
`imladris-bot.service` и `imladris-editor.service`. Они запускаются после
перезагрузки сервера и перезапускаются при завершении процесса.

[Каноническая инструкция установки и передачи](deploy/README.md) описывает
сборку первого комплекта, настройку закрытых env-файлов, проверку моделей,
автозапуск и подключение Windows. Редактор слушает `127.0.0.1:8765` и работает
с одним worker. Для бота нужен исходящий доступ к ВК, публичный порт не нужен.

При обновлении работающего сервиса переносите только проверенные изменения
кода и зависимостей. **Не заменяйте целиком рабочие `gallery/` и `data/`**:
там находятся изменения автора, согласия, открытые сеансы и состояние Long Poll.
Архив первого развёртывания предназначен для пустой установки.
Не запускайте две копии бота с одним ключом сообщества.

## Разработка и проверки

Из каталога проекта подготовьте Python 3.11 и установите зависимости:

```sh
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Тесты используют временные каталоги и подменяют сетевые адаптеры; настоящий
VK-токен для них не нужен. На macOS пропустите прямой native-тест pipeline:

```sh
python -m pytest tests --ignore=tests/test_tryon_pipeline.py -q
node --test tests/test_editor_transforms.cjs
```

Настоящую обработку проверяйте на Linux с установленным `libseccomp` и моделями.
Следующая команда не обращается к ВК и не изменяет калибровки каталога:

```sh
python scripts/server_smoke.py --output data/audit/local-smoke
```

На macOS Linux-проверку можно запустить через имеющуюся Podman VM:
`bash scripts/validate_linux.sh --output data/audit/local-smoke`.
Отчёты и результаты остаются локальными рабочими файлами.

## Модели, референсы и данные

Рабочий каталог — `bot/jewelry/gallery/manifest.json`, изображения — рядом
с ним. Локальные модели находятся в `bot/tryon/models/`, цепочки — в
`bot/tryon/assets/`. Условия сторонних моделей и ограничения описаны в
[уведомлении о сегментации](docs/HAIR_MODEL_NOTICE.md) и
[уведомлении об экспериментальных моделях ушей](docs/EAR_MODELS_NOTICE.md).
Сохраняйте соответствующие уведомления и лицензии при распространении.

Семь необходимых референсов в `фото для калибровки/` оставлены для админки,
измерений и offline-проверок. Полный список проверяет сборщик
`scripts/build_deploy_bundle.py`.

Фотографии обычной примерки обрабатываются в памяти на сервере и возвращаются
во ВК. SQLite `data/consent/consent.sqlite3` хранит идентификаторы группы,
пользователя и диалога, версии текста и даты принятия/отзыва; изображений в ней
нет. База `data/sessions/sessions.sqlite3` хранит открытые сеансы без фото.
Секреты, пользовательские фото, рабочие SQLite-базы и локальные резервные
копии не публикуются. Указанная в согласии политика ВК относится к платформе;
отдельная политика Оператора в комплект не входит.
