# VK-бот «Примерочная украшений»

Бот для ВКонтакте: пользователь пишет название украшения из каталога (серьги,
кулон, кольцо, бусы, диадема, заколка, брошь или браслет), бот подсказывает,
какое фото прислать (лицо/руку/плечи в нужном ракурсе), и после получения фото
автоматически «примеряет» украшение — накладывает его картинку в нужное место
(на ухо, шею, палец, лоб, макушку, грудь или запястье) с учётом масштаба и
наклона.

## Как это устроено технически

1. **vkbottle** — общение с ВК (Bots Long Poll API): бот сам ходит в ВК за
   новыми сообщениями, отдельный сервер/домен/SSL для этого не нужен — ни
   локально, ни на сервере.
2. **mediapipe** — распознавание ключевых точек на фото пользователя:
   - Face Mesh — точки лица (серьги, диадема, заколка — для заколки макушка
     достраивается продолжением оси «подбородок — линия волос»: своей точки
     на макушке у модели нет);
   - Pose — точки плеч (кулон, бусы и брошь крепятся к шее/плечам/груди,
     а не к лицу);
   - Hands — точки кисти (кольцо — на безымянном пальце, браслет — на
     запястье).
3. **Pillow** — накладывает PNG-картинку украшения (с прозрачным фоном) на
   фото пользователя: масштабирует под размер лица/руки/плеч, поворачивает
   под наклон головы/пальца, и вставляет в нужную точку.

Проект уже включает 5 демонстрационных украшений с **условными
PNG-заглушками** (простые нарисованные формы, не настоящие фото) — чтобы вы
могли сразу проверить всю цепочку целиком. Для реального каталога замените их
своими фотографиями украшений — см. [bot/jewelry/gallery/README.md](bot/jewelry/gallery/README.md).

### Важное ограничение по точности

Это эвристическая (приближённая) примерка, а не «настоящий» AR/3D-рендеринг:
mediapipe даёт хорошие координаты лица/тела/руки, но не идеальные (например,
у Face Mesh нет отдельных точек именно для мочек ушей — только контур щеки на
уровне уха). Для большинства фото результат выглядит правдоподобно, но на
нестандартных ракурсах украшение может сесть чуть не так. Для этого в
каталоге у каждого украшения есть поля тонкой подстройки
(`anchor_scale`, `offset_x`, `offset_y`, `rotation_offset`).

## Что понадобится

- Python **3.11** (рекомендуется). У `mediapipe` довольно строгие требования
  к версии Python и обычно нет поддержки самых свежих версий (3.13/3.14) —
  если у вас на компьютере уже стоит более новый Python (проверьте
  `python3 --version`), поставьте рядом 3.11 через `pyenv` (см. ниже),
  не трогая системный Python.
- Сообщество (группа) ВКонтакте, которым вы управляете — бот работает от её
  имени.
- macOS/Linux с доступом в интернет (тестировать можно прямо с вашего
  компьютера, без домена и статического IP).

## Шаг 1. Получаем токен сообщества ВК

1. Откройте **vk.com → ваше сообщество → Управление сообществом → Работа с API → Ключи доступа**.
2. Нажмите «Создать ключ», отметьте права: **фотографии, документы, сообщения
   сообщества** (Photos, Docs, Messages).
3. Скопируйте токен — он понадобится в `.env`.
4. Там же, в разделе **Сообщения сообщества**, включите приём сообщений
   («Сообщения сообщества» → «Включить»). Это и есть Bots Long Poll API,
   vkbottle настраивает нужные версии/параметры автоматически при первом
   запуске.
5. Запишите **ID сообщества** (число без минуса) — он указан в
   Управление сообществом → Информация → внизу страницы, либо в адресной
   строке `vk.com/club<ID>`.

Пока сообщество не опубликовано, писать боту смогут только
администраторы/редакторы сообщества — этого достаточно для тестирования.

## Шаг 2. Тестовый запуск с компьютера

Все команды — для macOS/zsh (вы на Mac). Выполняются из папки проекта.

### 2.1. Ставим Python 3.11 отдельно от системного (через pyenv)

```bash
brew install pyenv
pyenv install 3.11.9
```

### 2.2. Создаём и активируем виртуальное окружение проекта

```bash
cd vk_jewelry_bot
~/.pyenv/versions/3.11.9/bin/python3.11 -m venv .venv
source .venv/bin/activate
```

(После `source .venv/bin/activate` в начале строки терминала появится
`(.venv)` — значит окружение активно; так нужно делать в каждой новой сессии
терминала перед запуском бота.)

### 2.3. Ставим зависимости

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Если на этом шаге `mediapipe` не устанавливается под вашу версию/архитектуру
Python — см. раздел «Возможные проблемы» ниже.

### 2.4. Заполняем конфиг

```bash
cp .env.example .env
```

Откройте `.env` в редакторе и вставьте:

```
VK_TOKEN=токен_из_шага_1
VK_GROUP_ID=ID_сообщества_из_шага_1
```

### 2.5. (Уже сделано, но на всякий случай) генерируем демо-украшения

```bash
python scripts/generate_placeholder_gallery.py
```

Создаст 5 PNG-заглушек в `bot/jewelry/gallery/` — чтобы сразу можно было
проверить бота, ещё не имея реальных фото украшений.

### 2.6. Прогоняем офлайн-тесты (без VK, без mediapipe — быстрая проверка логики)

```bash
pip install pytest
pytest tests/ -v
```

Должны пройти все тесты — это проверяет поиск по каталогу и математику
наложения картинки (что украшение не «уезжает» при повороте).

### 2.7. Запускаем бота

Из папки `vk_jewelry_bot` в окружении с установленными зависимостями:

```bash
python run.py
```

Если терминал открыт на уровень выше (в папке репозитория):

```bash
python vk_jewelry_bot/run.py
```

Также поддерживаются `python -m bot` и `python -m bot.app` из папки
`vk_jewelry_bot`. Прямой запуск `bot/app.py` (например, кнопкой Run File
в редакторе) перенаправляется в `run.py`. В редакторе выберите тот же
интерпретатор Python, в котором установлены зависимости проекта.

Файл `.env` читается из `vk_jewelry_bot/.env`; относительный `TMP_DIR`
считается от `vk_jewelry_bot`, независимо от текущей папки терминала.
Уже заданные переменные окружения имеют приоритет над `.env`.

В логе должно появиться сообщение о запуске и (через vkbottle) о подключении
к Long Poll. Бот теперь работает **прямо с вашего компьютера** — отдельно
поднимать сервер/порт/домен не нужно, т.к. бот сам, как клиент, стучится в ВК
за новыми сообщениями.

### 2.8. Проверяем в реальном диалоге

1. Зайдите в свою группу в приложении/на сайте ВК под администратором.
2. Нажмите «Написать сообщение» (иконка сообщений сообщества).
3. Напишите `начать` — должно прийти приветствие.
4. Напишите `каталог` — список демо-украшений.
5. Напишите точное название, например `Серьги Луна`.
6. Пришлите в ответ подходящее фото (см. инструкцию, которую пришлёт бот).
7. Дождитесь ответа с фото — на нём должно появиться украшение.

Остановить бота — `Ctrl+C` в терминале.

## Шаг 4. Переносим бота на сервер

Локальный тест и серверный запуск используют **один и тот же код** — меняется
только то, где и как процесс запущен и перезапускается при сбое/перезагрузке.
Ниже — два варианта, выберите один.

### Вариант А: обычный сервер (Ubuntu) + systemd — рекомендуется

Подойдёт любой недорогой VPS с Ubuntu 22.04/24.04 (Timeweb Cloud, Selectel,
VK Cloud, Reg.ru и т.п.). Открывать входящие порты в файрволе **не требуется**
— бот сам инициирует соединение с ВК.

**4.1. Подключаемся и готовим сервер**

```bash
ssh root@ваш_ip
adduser --disabled-password botuser
apt update && apt install -y python3.11 python3.11-venv git
```

(Если в репозиториях Ubuntu нет python3.11 — добавьте PPA
`deadsnakes`: `add-apt-repository ppa:deadsnakes/ppa && apt update`.)

**4.2. Копируем проект на сервер**

Из терминала на своём компьютере (не на сервере), из папки, где лежит
`vk_jewelry_bot`:

```bash
rsync -av --exclude .venv --exclude .env --exclude data/tmp \
  vk_jewelry_bot/ root@ваш_ip:/opt/vk_jewelry_bot/
```

(Или через `git`: запушьте проект в свой приватный репозиторий и сделайте
`git clone` на сервере в `/opt/vk_jewelry_bot`.)

**4.3. Права и виртуальное окружение на сервере**

```bash
chown -R botuser:botuser /opt/vk_jewelry_bot
su - botuser
cd /opt/vk_jewelry_bot
python3.11 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
nano .env   # вставить боевой VK_TOKEN / VK_GROUP_ID
python scripts/generate_placeholder_gallery.py   # если ещё не переносили свои картинки
exit         # обратно под root
```

**4.4. Настраиваем systemd, чтобы бот работал постоянно и сам перезапускался**

```bash
cp /opt/vk_jewelry_bot/systemd/vk-jewelry-bot.service /etc/systemd/system/
nano /etc/systemd/system/vk-jewelry-bot.service   # проверьте пути и User=botuser
systemctl daemon-reload
systemctl enable --now vk-jewelry-bot
systemctl status vk-jewelry-bot
```

**4.5. Смотрим логи**

```bash
journalctl -u vk-jewelry-bot -f
```

**4.6. Обновление кода в будущем**

```bash
rsync -av --exclude .venv --exclude .env --exclude data/tmp \
  vk_jewelry_bot/ root@ваш_ip:/opt/vk_jewelry_bot/
ssh root@ваш_ip 'systemctl restart vk-jewelry-bot'
```

### Вариант Б: Docker / docker-compose

Если на сервере уже есть Docker — можно не возиться с системным Python:

```bash
rsync -av --exclude .venv --exclude data/tmp \
  vk_jewelry_bot/ root@ваш_ip:/opt/vk_jewelry_bot/
ssh root@ваш_ip
cd /opt/vk_jewelry_bot
cp .env.example .env && nano .env   # заполнить VK_TOKEN / VK_GROUP_ID
docker compose up -d --build
docker compose logs -f
```

Обновление — `git pull`/`rsync` новых файлов, затем
`docker compose up -d --build`.

## Возможные проблемы

- **`mediapipe` не ставится / нет колеса под вашу платформу** — почти всегда
  дело в версии Python. Убедитесь, что активировано именно окружение на
  Python 3.11 (`python --version` внутри `.venv`/`venv`), а не системный
  Python. Если и на 3.11 не встаёт — проверьте страницу `mediapipe` на PyPI,
  какие версии Python она поддерживает на текущий момент, и при необходимости
  используйте ближайшую поддерживаемую.
- **Apple Silicon (M1/M2/M3/M4)** — актуальные версии `mediapipe` и
  `opencv-python-headless` ставятся нативно через `pip` без Rosetta; если
  всё же ловите ошибки сборки — попробуйте более новую/старую версию из
  диапазона в `requirements.txt`.
- **`F0000 ... Check failed: service_ Service is unavailable` / крэш процесса
  при первом же фото на macOS** — это реальный баг, который я поймал и
  исправил при тестировании: свежий `mediapipe` (Tasks API — `FaceLandmarker`
  /`PoseLandmarker`/`HandLandmarker`) на macOS падает, если не передать явно
  `BaseOptions(delegate=BaseOptions.Delegate.CPU)` — без этого он пытается
  использовать GPU/Metal-путь и падает с ошибкой `graph_service.h`. В коде
  бота (`bot/tryon/landmarks_*.py`) этот параметр уже стоит явно — если вы
  правили эти файлы и убрали его, верните обратно. Проверено на Python 3.11 +
  mediapipe 0.10.35 на Apple Silicon (macOS); тест-регрессия на этот случай —
  `tests/test_tryon_pipeline.py`.
- **`mediapipe` предыдущих версий использовал `mp.solutions.FaceMesh/Hands/Pose`
  — в актуальных версиях этого модуля больше нет** (только `mediapipe.tasks`).
  Код бота уже переписан под новый Tasks API и требует файлы моделей
  `bot/tryon/models/*.task` (уже лежат в репозитории, отдельно скачивать
  не нужно).
- **На Ubuntu-сервере `opencv`/`mediapipe` падают с `ImportError: libGL.so.1`** —
  поставьте `apt install -y libgl1 libglib2.0-0` (в Dockerfile это уже учтено).
- **Бот не отвечает** — проверьте: включены ли «Сообщения сообщества» в
  настройках группы; правильный ли `VK_GROUP_ID`; не истёк/не отозван ли
  токен; смотрите логи (`journalctl -u vk-jewelry-bot -f` или вывод в
  терминале при локальном запуске) — vkbottle обычно ясно пишет причину
  (неверный токен, не хватает прав/scope и т.п.).
- **Часть кода ориентирована на vkbottle 4.x** (`bot.run_forever()`,
  `PhotoMessageUploader`, `BaseStateGroup`, `state=...` в `@bot.on.message`).
  Если после `pip install` у вас окажется сильно другая версия и что-то из
  этого не импортируется — откройте `pip show vkbottle` и примеры в
  официальном репозитории vkbottle на GitHub, чтобы поправить 1-2 места
  импорта под установленную версию.
- **Примерка не находит лицо/руку/плечи** — бот сам подскажет, что не так
  (текст ошибки из `TryOnError` в `bot/tryon/pipeline.py`); попросите более
  чёткое фото анфас с хорошим освещением, без сильного наклона.

## Что можно улучшить дальше (не реализовано, но заложено в архитектуру)

- Более точное позиционирование серёг/диадемы — например, обучить/подключить
  отдельную модель детекции именно ушей.
- Хранение состояния диалога в Redis (`vkbottle` поддерживает подключаемые
  `StateDispenser`) — нужно только если бот будет работать в нескольких
  процессах одновременно; для одного процесса текущий вариант (в памяти)
  достаточен.
- Админ-панель/команда для перезагрузки каталога без перезапуска процесса
  (`catalog.reload()` уже есть — осталось повесить на команду в чате).


## Проверка точности автоматической посадки серёг

Разметка калибровочных фото, измеримый отчёт и экспериментальный режим
сегментации ушей описаны в [scripts/ear_calibration/README.md](scripts/ear_calibration/README.md).
Без `EAR_PARSER_MODEL` бот сохраняет прежнюю геометрическую посадку.
Исследовательские веса не включены: их условия не разрешают коммерческое
использование без отдельного разрешения.
